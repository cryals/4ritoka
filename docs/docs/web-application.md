# Web-приложение Fabriq

Каталог `web/` содержит не только интерфейс, но и application layer: авторизацию, REST route handlers, SQLite, встроенную очередь расчётов, экспорт и восстановление задач после перезапуска. Расчётная логика остаётся в отдельном Python-сервисе.

## Страницы

| Маршрут | Назначение |
| --- | --- |
| `/login` | Вход и регистрация |
| `/dashboard` | Сводка по сценариям и последним запускам |
| `/scenarios` | Preset-конфигурации и пользовательские сценарии |
| `/scenarios/new` | Создание сценария вручную или из preset |
| `/scenarios/[id]` | Просмотр и редактирование сценария |
| `/runs` | История запусков и статусы |
| `/runs/new` | Настройка и постановка расчёта в очередь |
| `/runs/[id]` | Метрики, графики, рекомендации и журнал событий |
| `/compare` | Сравнение от 2 до 10 завершённых запусков |

В production приложение опубликовано под base path `/fabriq`.

## Внутренние слои

```text
app/            страницы и REST route handlers
components/     формы, редактор, графики и рабочие представления
lib/auth.ts     cookie-session и хеширование паролей
lib/db.ts       схема SQLite и операции с данными
lib/runner.ts   очередь, workers, recovery и backup timer
lib/python-client.ts  HTTP-клиент FastAPI
lib/validation.ts     Zod-контракты входных данных
lib/types.ts          TypeScript-контракты ответа
```

## Авторизация и изоляция

Пароли хешируются `scrypt` с индивидуальной случайной солью. Случайный session token сохраняется у клиента в `HttpOnly`, `SameSite=Lax` cookie, а в базе находится только SHA-256 hash токена. Срок сессии по умолчанию — 30 дней.

Все запросы к сценариям и запускам фильтруются по `user_id`. Изменяющие route handlers проверяют origin запроса. Первый зарегистрированный пользователь получает роль `admin`, следующие — `user`.

## Схема SQLite

При первом подключении автоматически создаются таблицы:

- `schema_migrations` — применённые версии схемы;
- `users` — email, hash пароля, роль и язык;
- `sessions` — hash токена и срок действия;
- `scenarios` — пользовательская конфигурация и версия формата;
- `simulation_runs` — snapshot сценария, параметры и жизненный цикл задачи;
- `simulation_results` — аналитика, отчёт, event log и полный payload.

SQLite работает с `foreign_keys=ON`, `journal_mode=WAL` и `busy_timeout=5000`. Индексы ускоряют выдачу пользовательских сценариев, истории и очереди.

## Очередь и жизненный цикл

`POST /api/runs` валидирует запрос, сохраняет snapshot конфигурации и возвращает `202 Accepted`. Runner поддерживает два набора: FIFO-очередь идентификаторов и множество активных задач. Число одновременно выполняемых расчётов задаёт `FABRIQ_MAX_CONCURRENT_RUNS`.

Перед запуском worker атомарно меняет `pending` на `running`. После ответа Python API результат и статус `completed` сохраняются одной транзакцией. Исключение переводит задачу в `failed`; пользовательская отмена — в `cancelled`.

При старте процесса все оставшиеся `running` возвращаются в `pending`, после чего незавершённые задачи снова добавляются в очередь. Поэтому перезапуск не оставляет их навсегда в промежуточном состоянии.

## Retention и резервные копии

При старте и затем раз в семь дней удаляются завершённые, отменённые и ошибочные запуски старше `FABRIQ_RETENTION_DAYS` — по умолчанию 7 дней. Отдельная очистка старых `failed/cancelled` записей поддерживает совместимость с `FABRIQ_TERMINAL_RUN_RETENTION_DAYS`.

Периодический backup timer запускается раз в `FABRIQ_BACKUP_INTERVAL_HOURS`, по умолчанию раз в 24 часа. Он использует SQLite backup API и пишет копии в `FABRIQ_BACKUP_DIR`.

## Локальный запуск

В первом терминале:

```bash
python -m uvicorn python_service.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
cd web
npm ci
npm run dev
```

Откройте `http://127.0.0.1:3000`.

## Проверки

```bash
cd web
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
```

## Резервное копирование

```bash
cd web
npm run backup
npm run backup:verify -- ./backups/<backup-file>.db
```

Резервные копии нужно переносить на отдельный носитель или объектное хранилище. Для восстановления остановите web-процесс, замените файл базы проверенной копией и снова запустите приложение.

## Ограничения выбранной архитектуры

Встроенная очередь и SQLite рассчитаны на один экземпляр web-процесса. Для текущего учебного и небольшого рабочего контура это уменьшает число сервисов и упрощает backup. Перед горизонтальным масштабированием потребуется вынести очередь в отдельный broker и заменить SQLite на серверную СУБД. Python-движок при этом менять не нужно.
