# Fabriq Windows launcher design

## Goal

Один `START-FABRIQ.bat` из корня репозитория подготавливает и запускает Fabriq на Windows без ручного открытия нескольких терминалов.

## Commands

- Без аргументов или `start`: проверить окружение, установить зависимости, собрать проект и запустить сервисы.
- `status`: показать состояние API, web-приложения и презентации по PID и HTTP.
- `stop`: завершить сохранённые деревья процессов и удалить устаревшие PID-файлы.
- `logs`: открыть папку `.temp`.

## Preconditions

- Python 3.11 или новее. Версия нужна для `asyncio.timeout`.
- Node.js 20 или новее.
- npm должен находиться в `PATH`.

Скрипт выводит найденные версии. Если системной зависимости нет или версия устарела, запуск останавливается с понятным сообщением.

## Preparation

1. Перейти в корень репозитория относительно расположения BAT.
2. Создать `.temp`.
3. Создать `.venv`, если окружение отсутствует.
4. Установить Python-пакеты из `requirements.txt`.
5. Выполнить `npm ci` в `web`.
6. Проверить импорт Python-модулей и выполнить `npm run typecheck`.
7. Собрать Next.js командой `npm run build`.

## Runtime

- FastAPI: `127.0.0.1:8000`.
- Next.js production server: `127.0.0.1:3000`.
- HTML-презентация: `127.0.0.1:8080`.

Каждый сервис запускается скрытым процессом. PID сохраняется в `.temp`. Стандартный вывод и ошибки каждого процесса пишутся в отдельные лог-файлы в этой же папке.

## Safety and errors

- Если управляемый сервис уже работает и отвечает, второй экземпляр не запускается.
- Если порт занят неизвестным процессом, скрипт останавливается и сообщает номер порта.
- После запуска BAT ожидает готовность каждого HTTP endpoint с ограниченным таймаутом.
- При сбое показывается путь к соответствующему логу.
- `stop` завершает только процессы из сохранённых PID-файлов вместе с их дочерними процессами.

## Success criteria

- Двойной клик запускает API, web-приложение и презентацию.
- В браузере открываются `http://127.0.0.1:3000` и `http://127.0.0.1:8080`.
- Все диагностические сообщения доступны в `.temp`.
- Повторный запуск не создаёт дубликаты процессов.
