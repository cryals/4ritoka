# Fabriq user flow slides design

## Goal

Разделить пользовательский путь и технический путь задачи на два последовательных слайда, чтобы объяснение было понятно и пользователю, и технической комиссии.

## Slide 6: User flow

Один горизонтальный timeline с шестью крупными этапами: выбрать сценарий, задать условия, запустить, дождаться расчёта, изучить результат, сравнить варианты. Жёлтым отмечаются запуск и итоговое решение. Подписи объясняют действие пользователя, а не внутреннюю реализацию.

## Slide 7: System flow

Блок-схема с четырьмя слоями: Browser, Next.js application layer, SQLite and queue, FastAPI and Python engine. Между блоками показывается жизненный цикл одной задачи: `pending → running → completed`. Внизу отдельный контур результата: analytics, event log, compare.

## Deck changes

- Интерфейс переезжает на слайд 8.
- Результаты переезжают на слайд 9.
- В нумерации всех слайдов используется `09`.
- Текст доклада синхронизируется с двумя новыми слайдами.

## Validation

- Desktop, mobile portrait и landscape не имеют нежелательного горизонтального overflow.
- Оба flow читаются слева направо и не требуют мелкого текста.
- Все стрелки и соединители остаются декоративными, а доступное текстовое описание присутствует в DOM.
- Навигация, хэши и клавиатура продолжают работать после увеличения числа слайдов.
